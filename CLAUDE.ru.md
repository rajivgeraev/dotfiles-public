# CLAUDE.md

> Русская версия для чтения. Основной файл, который использует Claude Code — [CLAUDE.md](./CLAUDE.md).
> Эта версия — перевод для человека и не поддерживается автоматически вне текущей сессии.

Этот файл даёт Claude Code (claude.ai/code) контекст для работы с кодом в этом репозитории.

## Что это такое

Репозиторий dotfiles для macOS под управлением [chezmoi](https://www.chezmoi.io), в паре с Homebrew. Это
*source directory* (исходная директория) chezmoi — файлы здесь следуют соглашениям об именовании chezmoi и не
являются теми же файлами, что окажутся на диске. Здесь нет сборки/линтера/тестов; изменения проверяются через
рендеринг/diff/apply в chezmoi и через реальное использование получившегося shell-конфига.

## Соглашения об именовании chezmoi

Исходные файлы здесь следуют стандартному именованию chezmoi: `dot_foo` → `~/.foo`, `private_foo` → права
`0600`, `*.tmpl` → рендерится как Go-шаблон перед записью, `run_once_*`/`run_onchange_*`/`before_`/`after_` → скрипты (порядок выполнения ниже).
Полный общий справочник по атрибутам именования chezmoi живёт в памяти проекта (собирается заново на каждой
машине — см. последний раздел), а не дублируется здесь.

- `.chezmoiignore` также исключает `.keep` — маркер, которым git удерживает иначе пустые каталоги
  (`dev/gh`, `dev/sandbox`, `sync/obsidian`). chezmoi создаёт каталог, но маркер в него не копирует.
  Это документированный способ получить пустой каталог; прежнее имя `.chezmoikeep` работало лишь
  случайно — префикс `.chezmoi*` зарезервирован, — и `chezmoi doctor` ругался на него как на
  подозрительную запись.
- `.chezmoiignore` сейчас исключает `README.md`, `Brewfile`, `CLAUDE.md`, `CLAUDE.ru.md` — эти файлы лежат в
  репозитории для документации/сборки пакетов, но сами по себе не являются dotfiles.
- `.chezmoi.toml.tmpl` — это шаблон собственного конфига chezmoi (рендерится один раз при `chezmoi init` в
  `~/.config/chezmoi/chezmoi.toml`), содержащий `[data]` для шаблонов (имя/почта).
  Секции `[age]` в нём намеренно нет — см. раздел «Секреты» ниже.

Конфиг под опциональный инструмент гейтится в **рантайме шелла**, а не на этапе рендера шаблона chezmoi —
сознательно не через `{{ if lookPath }}`/`{{ if stat }}` в `.tmpl`. Shell-интеграция каждого инструмента лежит
в своём файле в `dot_config/zsh/conf.d/<tool>.zsh`, с гейтом в первой строке (`command -v <tool> >/dev/null 2>&1
|| return`, либо `[[ -d ${HOMEBREW_PREFIX:-/opt/homebrew}/opt/<formula> ]] || return` для директории,
поставленной через Homebrew — как сделано для antidote). `dot_zshrc` перечисляет, какие файлы из `conf.d`
сорсить, явными массивами (`typeset -a`), а не glob'ом, и подключает их циклом — массивы служат явным
allowlist'ом, поэтому случайно оставленный в `conf.d/` файл сам по себе никогда не подхватится.

Подключение идёт в **две фазы**, между которыми вызывается `compinit`: fzf-tab обязан загрузиться после
`compinit`, но раньше плагинов, оборачивающих виджеты zle. Фаза 1 (`zsh_conf_pre`, сейчас только
`antidote-pre`) грузит `.zsh_plugins.txt` — там лишь плагины завершений с аннотацией `kind:fpath`. Фаза 2
(`zsh_conf_post`, начинается с `antidote-post`) грузит `.zsh_plugins_post.txt`: fzf-tab первым,
autosuggestions и syntax-highlighting последними. Внутри фазы порядок файлов по-прежнему не важен, а вот
порядок строк в `.zsh_plugins_post.txt` — важен. Следуйте этому паттерну при добавлении конфига
для нового опционального CLI-инструмента. Это заменило более раннюю схему с `lookPath` в шаблоне именно потому,
что `lookPath` проверяет `$PATH` **собственного процесса** chezmoi, зафиксированный на момент старта `chezmoi
apply` — при восстановлении с нуля `bootstrap.sh` ставит Homebrew и все инструменты незадолго до того, как
chezmoi вообще запустится, поэтому проверка на этапе рендера успевала устареть и собирала блок пустым. Проверка `command -v`
в рантайме вычисляется заново при каждом запуске шелла, поэтому корректна с первого прохода независимо от
порядка установки — подробное обоснование в заметке памяти про этот редизайн.

## Порядок применения

Справочник повседневных команд (`chezmoi diff`/`apply`/`edit`/`add`/`update`) — в разделе «Рабочий процесс»
`README.md`, здесь не повторяется. Что важно для корректности и *специфично для этого репозитория*:

Все скрипты лежат в `.chezmoiscripts/`, поэтому выполняются как обычно, но не создают записей в целевом
состоянии.

**Установка софта — не задача chezmoi.** `bootstrap.sh` в корне репозитория это отдельный императивный шаг,
выполняемый один раз на чистой машине: Xcode CLT, Homebrew, затем `brew bundle` по `Brewfile`. Он указан
в `.chezmoiignore`, поэтому в `$HOME` не попадает. Разделение существует потому, что установка — однократное
императивное действие, а chezmoi описывает желаемое состояние, к которому сходится многократно. Пока они были
смешаны, `chezmoi verify` отчитывался об установке пакетов, а один сбойный каск обрывал всё восстановление.

Поэтому `chezmoi apply`/`init --apply` выполняет: сначала обычные файлы, шаблоны и externals, затем два
`after_`-скрипта в числовом порядке — `run_onchange_after_20-rebuild-bat-cache.sh.tmpl` (`bat cache --build`,
триггерится хешами `.chezmoiexternal.toml` и файла синтаксиса) и
`run_onchange_after_30-set-macos-defaults.sh.tmpl` (`defaults write` для Finder/Dock/меню-бара/звука).
Числовые префиксы задают порядок явно, а не через ASCII-сортировку имён; пропуск на `10-` — там раньше был
скрипт установки Brewfile.

Темы объявлены в `.chezmoiexternal.toml`, а не качаются скриптом: chezmoi кэширует их, сверяет содержимое
при каждом apply/diff/verify, и сетевой сбой больше не обрывает весь apply. Пересборка кеша bat помечена
`after_` намеренно — она обязана видеть файлы тем и синтаксиса уже на диске; полагаться в этом на
ASCII-порядок имён было хрупко.

Репозиторий **публичный и не содержит секретов вообще** — ни открытым текстом, ни в зашифрованном виде.
Шифрование защищает содержимое, но опубликованный шифротекст скачивается навсегда и расшифровывается
задним числом при любой будущей утечке ключа; проще не публиковать его совсем. Шифрование `age` было
сознательно убрано при переходе на публичный репозиторий, поэтому здесь нет ни `key.txt`, ни файлов
`encrypted_*.age`, ни секции `[age]` в `.chezmoi.toml.tmpl`.

Секретами считаются три файла; они лежат в менеджере паролей и раскладываются `restore-secrets.sh`
(он же выставляет режим 0600 — раньше это делал chezmoi через префикс `private_`):

- `~/.config/rclone/rclone.conf` — токены и пароли к удалённым хранилищам
- `~/.local/share/atuin/key` — ключ E2E-синка Atuin; без него `atuin login` не расшифрует облачную историю
  даже с верным паролем. Сам пароль от аккаунта здесь тоже не хранится: у `atuin login` нет входа по
  токену, только `-u`/`-p`/`-k`, поэтому он вводится вручную при восстановлении.
- `~/.ssh/id_ed25519_gh` — приватный SSH-ключ. Его `.pub` и `~/.ssh/config` секретами не являются и
  остаются в репозитории.

**Перед `chezmoi add` файл нужно открыть и просмотреть.** Кроме очевидных учётных данных секретом
считается всё, что раскрывает инфраструктуру: имена rclone-remote'ов, адреса серверов, названия облачных
провайдеров. Именно из-за этого при создании репозитория был убран `sync-mac.sh` — он называл провайдера
хранилища и точную структуру путей на нём. Если появляется новый секрет, его путь дописывается в `ITEMS`
внутри `restore-secrets.sh`, а не в source state.

## Управляемые инструменты/стек

- Shell: zsh с antidote (менеджер плагинов), starship (промпт), atuin (история команд, тема Catppuccin Mocha
  Mauve, залогинен облачный синк — про его ключ см. раздел «Шифрование» выше) — все в теме Catppuccin Mocha.
- Полный список CLI/GUI-пакетов — в `Brewfile`, здесь не дублируется: читай его напрямую, а не полагайся, что
  этот файл с ним синхронизирован.
- Из GUI-casks управляемый через chezmoi конфиг есть у Ghostty, Zed (`dot_config/zed/`), глобальных
  настроек Claude Code (`dot_claude/settings.json` — только глобальные предпочтения: `theme`, `tui`,
  `model`, `language`, `voice`; а не вся остальная `~/.claude/`,
  которая представляет собой runtime-состояние сессий/телеметрии и никогда не должна добавляться целиком) и
  Karabiner-Elements (`dot_config/karabiner/karabiner.json` — переключение раскладки тапом Cmd; выдача
  разрешений macOS/Accessibility/driver-extension — ручная, описана в `karabiner-recovery.md`, не
  автоматизируется); у остальных приложений конфига, достойного версионирования, не нашлось (проверялись их
  preferences-домены/Application Support — либо чистое UI/session-состояние, либо, как у Easydict, вперемешку
  с полной историей переводов, которой не место в git). Перед тем как считать «конфига нет» верным для нового
  cask — перепроверь его реальные preferences/Application Support.
- `dot_zshenv` хранит переменные окружения, которые обязан видеть каждый zsh: четыре базовые XDG-директории
  и `$ZDOTDIR`, выводимый из `XDG_CONFIG_HOME`. Им место именно здесь, а не в `dot_zshrc`: `.zshrc` читают
  только интерактивные шеллы, поэтому скрипты, LaunchAgent'ы и `zsh -c` остались бы без них. Держите этот
  файл свободным от алиасов, вывода и медленных вызовов.
- `$ZDOTDIR` установлен в `~/.config/zsh` (в `dot_zshenv`), поэтому собственные dotfiles zsh лежат в
  `dot_config/zsh/` (`dot_zprofile`, `dot_zshrc`, `conf.d/*.zsh`, `dot_zsh_plugins{,_post}.txt` для antidote), а не в
  `~/.zshrc`.
- `zconf` (определена в конце `dot_zshrc`) — вспомогательная shell-функция: `zconf` открывает исходник
  zshrc для редактирования через `chezmoi edit`, `zconf -r` пересобирает текущий zshrc.
- Identity git берётся из `dot_config/git/config.tmpl`, использующего `.name`/`.email`, уже объявленные в
  `[data]` `.chezmoi.toml.tmpl` — отдельный ручной шаг не нужен.
- `~/dev/{sandbox,gh}` и `~/sync/obsidian` восстанавливаются пустыми через файлы-маркеры `.chezmoikeep`
  (механизм chezmoi для коммита иначе нетрекаемых пустых директорий) — намеренно без `exact_`, чтобы chezmoi
  никогда не удалял то, что человек туда потом положит.

## Память Claude Code для этого проекта

Auto memory здесь остаётся в дефолтном месте Claude Code (`~/.claude/projects/<project>/memory/`) — намеренно
**не** перенесена в репозиторий. Дефолт уже привязан к проекту (закреплён за этим репозиторием, общий для
любой сессии, запущенной в этой директории, никогда не попадает в git) и не требует переопределения настроек,
чтобы выполнить условие «записано один раз — доступно всему проекту, а не только одной сессии». Если это
когда-нибудь потребуется пересмотреть — обоснование лежит в памяти проекта, здесь не повторяется.

## Бутстрап новой машины / новой сессии

Пошаговая инструкция восстановления в README.md заканчивается запуском `claude` в этой директории на только что
восстановленной машине. Память (см. выше) машинно-локальная и там ещё не будет существовать, хотя этот файл уже
будет (он приезжает вместе с git-клоном).

Если память проекта пуста или в ней не хватает тем в начале сессии здесь — собери её в таком порядке, один раз
на машину (сначала проверь, что уже есть; не переисследуй тему, по которой заметка памяти уже существует):

1. **Сначала — сам Claude Code.** Найди актуальные официальные best-practice (структура/размер `CLAUDE.md`,
   конвенции auto memory, эффективные паттерны работы) в официальной документации Anthropic и сохрани их в
   память прежде всего остального — это должно определить, как дальше пройдёт весь бутстрап и последующая
   работа здесь.
2. **Все инструменты этого репозитория, а не только chezmoi.** Прочитай `Brewfile` напрямую, чтобы получить
   актуальный список CLI/GUI-инструментов — не хардкодь его здесь, он меняется вместе с Brewfile. Для chezmoi
   и каждого инструмента проверь, есть ли уже заметка в памяти; для тех, кого нет — найди актуальную
   документацию и сохрани заметку. Соизмеряй усилия с тем, насколько сильно поведение/дефолты инструмента
   реально меняются и важны здесь: chezmoi, atuin, starship, antidote и yazi стоят полноценного
   исследования; крайне стабильные, всем известные инструменты (curl, rsync, git, gh) требуют лишь беглой
   проверки актуального синтаксиса, а не полного мануала.

Смысл всего этого — не полагаться на потенциально устаревшие знания из обучения: дефолты и возможности
меняются между релизами и у chezmoi, и у этих инструментов. То, что память остаётся вне git и пересобирается
на каждой машине — сделано намеренно; цена — платить за это исследование один раз на новую машину, а не один
раз на сессию.

## Замечание про язык

`README.md` написан на русском языке; изменения в нём в дальнейшем оформляйте на русском для консистентности.

`CLAUDE.ru.md` — это человекочитаемый русский перевод этого файла (`CLAUDE.md`), для владельца репозитория;
сам Claude Code его как инструкции не читает. **При каждом изменении `CLAUDE.md` нужно в том же изменении
обновлять `CLAUDE.ru.md`** — точным и актуальным переводом того, что поменялось, не давая переводу разъехаться
с оригиналом. Правило действует в любой сессии, а не только в той, где оно было записано.
